5. PROBLEMAS ENCONTRADOS DURANTE EL DESPLIEGUE Y SOLUCIONES
--------------------------------------------------------------

5.1. Error: require_once(.../web/../app/Model.php): Failed to open
     stream: No such file or directory (index.php, linea 6)

     Causa: el archivo app/Model.php no existia en el servidor.
     No estaba bien subido al repositorio y lo habia copiado a
     mano al servidor despues del git clone. Despues, al borrarlo
     con rm y hacer git pull, Git no lo restauro (cuando un archivo
     se borra a mano, git pull no lo vuelve a crear).

     Diagnostico:
         ls -la ~/www/alimentos/app/
         find ~ -iname "model.php"
         git status
         git ls-files app

     Solucion: subir Model.php al repositorio desde mi ordenador
         git add app/Model.php
         git commit -m "Anado Model.php"
         git push origin main
     y en el servidor recuperar el archivo con git pull (o, si
     aparecia como "deleted" en git status, con
     git restore app/Model.php).

     Leccion: el servidor debe quedar siempre igual que GitHub.
     Los cambios se hacen en local, se suben con push y en el
     servidor solo se hace git pull. No se editan ni copian
     archivos a mano en el servidor.

5.2. Error: require(.../app/../views/templates/inicio.php): Failed
     to open stream (Controller.php, linea 12)

     Causa: la ruta del require en Controller.php apuntaba a una
     carpeta views/templates que no existe en este proyecto. Las
     plantillas estan en app/templates.

     Solucion: corregir las rutas en Controller.php para que usen
     app/templates.

5.3. Error: require(.../alimentos/apptemplates/inicio.php): Failed
     to open stream (Controller.php, linea 12)

     Causa: faltaba la barra entre app y templates. __DIR__ no
     termina en "/", asi que el require estaba escrito como
         __DIR__ . 'templates/inicio.php'

     Solucion: anadir la barra en todos los require del controlador:
         require __DIR__ . '/templates/inicio.php';

     Nota: este archivo es del integrante 3. La correccion se hizo
     en local, se subio a GitHub y en el servidor se hizo git pull.
     Habia una version de Controller.php modificada en el servidor
     (fecha 19 nov, 17:33), por lo que hubo que asegurarse de que
     la version buena fuera la del repositorio.
